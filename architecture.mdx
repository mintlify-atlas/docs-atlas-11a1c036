LexMetra is built as two independently runnable services: a **Next.js 16 frontend** that handles the inspector UI, authentication, image upload, and client-side compliance logic, and a **FastAPI Python backend** that exposes an OCR inspection API for image analysis. User accounts and sessions are stored in PostgreSQL via Prisma ORM, while inspection records are persisted client-side in `localStorage` — keeping field-use fast and offline-capable without requiring a database round-trip on every inspection.

The browser communicates exclusively with the Next.js frontend. The Next.js API routes talk to PostgreSQL (for auth) and can proxy requests to the FastAPI backend (for OCR). CORS on the FastAPI service is explicitly configured to accept requests from `localhost:3000` and `localhost:5173` only.

## Data Flow for an Inspection

<Steps>

### Inspector captures or uploads an image

The inspector either takes a photo in-browser or uploads a JPEG/PNG file of the product label from their device.

### Frontend compresses the image

The Next.js API route uses `sharp` (v0.35.4) to resize and compress the image server-side before returning a URL back to the browser, keeping payload sizes manageable on mobile connections.

### Frontend calls the FastAPI backend

The browser sends a `POST` request to `http://localhost:8000/api/inspect` as `multipart/form-data`, including the compressed image binary and the inspection metadata fields:

```python
# FastAPI endpoint signature (backend/main.py)
@app.post("/api/inspect")
async def inspect(
    image: UploadFile = File(...),
    product_name: str = Form(""),
    sale_type: str = Form("retail"),
    is_imported: bool = Form(False),
    net_quantity_grams_or_ml: float = Form(0)
):
```

### OCR engine processes the label

The backend reads the image bytes, runs OCR analysis against the label, and applies the Legal Metrology (Packaged Commodities) Rules to check each of the eight mandatory declarations.

### Backend returns the inspection result

The response includes an `inspection_id`, per-field declaration results, an `overall_status`, and confidence scores for each detected region.

### Compliance score is computed

The frontend calculates the numeric compliance score (0–100) from the declaration results and determines the overall status: `COMPLIANT`, `VIOLATION`, or `UNCERTAIN`.

### Result is saved to localStorage

The completed `Inspection` object is written to `localStorage` via `persistInspection()` in `lib/mock-services.ts`. The inspector can then review the result and click **"Save to register"** to mark it as `saved: true`.

</Steps>

## Client-Side Persistence

<Info>
  LexMetra uses a split-persistence model: **user accounts and sessions** live in PostgreSQL (managed by Better Auth and Prisma), while **inspection records** live entirely in the browser's `localStorage`.
</Info>

Inspection records are stored under the key **`the-inspectors-inspections`** as a JSON array of `Inspection` objects. The relevant fields are:

```typescript
// from frontend/lib/demo-data.ts
export type Inspection = {
  id: string;           // e.g. "LM-2026-0042"
  product: string;
  manufacturer: string;
  quantity: string;
  status: InspectionStatus;    // "COMPLIANT" | "VIOLATION" | "UNCERTAIN"
  summary: string;
  timestamp: string;           // ISO 8601
  dateLabel: string;           // human-readable label, e.g. "Today, 10:32 AM"
  declarations: Declaration[];
  evidence: EvidenceRegion[];
  image?: string;              // base64 or object URL
  saved: boolean;              // true = in compliance register
  score: number;               // 0–100
};
```

The helper functions in `lib/mock-services.ts` manage all reads and writes:

| Function | Behaviour |
|----------|-----------|
| `loadInspections()` | Reads and parses the `localStorage` array; returns `[]` on error |
| `saveInspections(inspections)` | Serialises and writes the full array back to `localStorage` |
| `persistInspection(inspection)` | Prepends a new or updated inspection, replacing any with the same `id` |
| `markInspectionSaved(id)` | Sets `saved: true` on a specific inspection (promotes to register) |
| `getInspectionById(id)` | Looks up a single inspection by ID |

<Warning>
  Because `localStorage` is browser- and device-scoped, inspection records are not shared between different devices or browsers. A server-side persistence layer is planned for production deployments to support multi-device access and departmental record-keeping requirements.
</Warning>
