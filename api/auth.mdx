LexMetra's authentication layer is powered by [Better Auth](https://www.better-auth.com/) with the Prisma adapter backed by PostgreSQL. All core auth routes — sign-in, sign-up, sign-out, and session retrieval — are automatically generated by Better Auth and exposed through a single Next.js catch-all handler. An additional protected route handles updating the authenticated user's profile image and is implemented as a standalone Next.js API route.

## Better Auth Base Routes

All standard auth routes are served through:

```
GET | POST /api/auth/[...all]
```

This catch-all is wired up in `app/api/auth/[...all]/route.ts`:

```typescript
import { auth } from "@/lib/auth";
import { toNextJsHandler } from "better-auth/next-js";

export const { GET, POST } = toNextJsHandler(auth);
```

Better Auth automatically generates and handles the following routes:

| Route | Method | Description |
|---|---|---|
| `/api/auth/sign-in/email` | POST | Sign in with email and password |
| `/api/auth/sign-up/email` | POST | Register a new account |
| `/api/auth/sign-out` | POST | Invalidate session and clear cookie |
| `/api/auth/session` | GET | Return the current session |

## POST /api/auth/sign-in/email

Signs in an existing user with email and password. On success, Better Auth sets an `HttpOnly` session cookie valid for **7 days** (as configured in `lib/auth.ts` with `expiresIn: 60 * 60 * 24 * 7`).

### Request Body

<ParamField body="email" type="string" required>
  The registered email address of the user.
</ParamField>

<ParamField body="password" type="string" required>
  The user's account password.
</ParamField>

### Example

```bash
curl -X POST http://localhost:3000/api/auth/sign-in/email \
  -H "Content-Type: application/json" \
  -c cookies.txt \
  -d '{"email": "inspector@example.com", "password": "s3cureP@ss"}'
```

### Response

On success, a session cookie is set and the response body contains the authenticated user object:

```json
{
  "user": {
    "id": "usr_abc123",
    "email": "inspector@example.com",
    "name": "Priya Sharma",
    "image": null,
    "createdAt": "2026-09-01T08:00:00.000Z",
    "updatedAt": "2026-09-05T10:30:00.000Z"
  },
  "session": {
    "id": "sess_xyz789",
    "expiresAt": "2026-09-12T10:30:00.000Z"
  }
}
```

## POST /api/auth/sign-up/email

Creates a new inspector account. On success, Better Auth creates the user record in PostgreSQL via Prisma and sets a session cookie.

### Request Body

<ParamField body="email" type="string" required>
  Email address for the new account. Must be unique.
</ParamField>

<ParamField body="password" type="string" required>
  Password for the new account.
</ParamField>

<ParamField body="name" type="string" required>
  Display name for the inspector (e.g. `"Priya Sharma"`).
</ParamField>

### Example

```bash
curl -X POST http://localhost:3000/api/auth/sign-up/email \
  -H "Content-Type: application/json" \
  -c cookies.txt \
  -d '{
    "email": "inspector@example.com",
    "password": "s3cureP@ss",
    "name": "Priya Sharma"
  }'
```

### Response

On success, the session cookie is set and the new user is returned in the response body. The user record is persisted in the `User` table via Prisma.

## GET /api/auth/session

Returns the active session for the current request. If no valid session exists, returns `null` or a `401` response depending on the Better Auth configuration.

### Example — From the Browser

```typescript
const res = await fetch("/api/auth/session", { credentials: "include" });
const data = await res.json();
console.log(data.user); // null if not signed in
```

### Example — From a Next.js Server Component

Use `auth.api.getSession` directly in Server Components or Route Handlers to avoid an extra HTTP round-trip:

```typescript
import { auth } from "@/lib/auth";
import { headers } from "next/headers";

const session = await auth.api.getSession({ headers: await headers() });

if (!session) {
  // User is not authenticated
}
```

## POST /api/auth/user/image

A protected Next.js API route that updates the authenticated user's profile image stored in the database. Implemented in `app/api/(auth)/user/image/route.ts`.

### Request Body

<ParamField body="image" type="string" required>
  Base64-encoded image string. The raw decoded size must not exceed **1 MB**. Passing a data URL prefix (e.g. `data:image/jpeg;base64,...`) is acceptable — the prefix is ignored during size validation.
</ParamField>

<Warning>
  Images are validated against a **1 MB** decoded size limit (`Buffer.byteLength(image, "base64") > 1024 * 1024`). Requests exceeding this limit are rejected immediately with HTTP `400` and the message `"Image too large (max 1MB)"`. This corresponds to roughly **750 KB** of raw image data before base64 encoding. Compress images client-side (e.g. using the `POST /api/upload` endpoint) before passing them here.
</Warning>

### Example

```bash
curl -X POST http://localhost:3000/api/auth/user/image \
  -H "Content-Type: application/json" \
  -H "Cookie: better-auth.session_token=<your-session-token>" \
  -d '{"image": "<base64-string>"}'
```

### Response

<ResponseField name="user" type="object">
  The updated user object as returned by Prisma after the image field is written.
</ResponseField>

```json
{
  "user": {
    "id": "usr_abc123",
    "email": "inspector@example.com",
    "name": "Priya Sharma",
    "image": "<base64-string>",
    "updatedAt": "2026-09-05T12:00:00.000Z"
  }
}
```

### Error Responses

| Status | Body | Condition |
|---|---|---|
| `401` | `{ "error": "Unauthorized" }` | No valid session cookie |
| `400` | `{ "error": "No image" }` | `image` field missing from request body |
| `400` | `{ "error": "Image too large (max 1MB)" }` | Decoded image exceeds 1 MB |
| `500` | `{ "error": "Update failed" }` | Prisma write failure |
| `500` | `{ "error": "Failed to update image" }` | Unexpected server error |

## POST /api/auth/sign-out

Invalidates the current session and clears the session cookie. No request body is required.

```bash
curl -X POST http://localhost:3000/api/auth/sign-out \
  -H "Cookie: better-auth.session_token=<your-session-token>"
```

On success, the session cookie is cleared and subsequent calls to `/api/auth/session` will return no active session.
